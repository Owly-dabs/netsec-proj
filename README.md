# swatad: ML attack detection on SWaT / WADI

Reproduces published unsupervised anomaly detectors (**USAD**, **GDN**) and two classical baselines (**PCA**, **Isolation Forest**) on the iTrust SWaT (Dec 2015) and WADI (A2, Nov 2019) water-treatment datasets. It evaluates them more strictly than the papers do, and adds plant-aware (per-stage) alarm logic.

Paradigm: semi-supervised. Models train on **normal data only**. Attack labels are used only for evaluation (and for the `best_f1` oracle threshold, which is always reported under that name).

Design rationale and the original task breakdown are in `IMPLEMENTATION_PLAN.md`. The course brief is in `instructions.md`.

## How to run

### 1. Setup (Python 3.10, CPU only)

```bash
python3.10 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
```

### 2. Get the data

The raw iTrust files are not in git. Request them from iTrust (SUTD) and place them as:

```
data/raw/swat/SWaT_Dataset_Normal_v1.xlsx
data/raw/swat/SWaT_Dataset_Attack_v0.xlsx
data/raw/wadi/WADI.A2_19 Nov 2019/WADI_14days_new.csv
data/raw/wadi/WADI.A2_19 Nov 2019/WADI_attackdataLABLE.csv
```

Convert once to Parquet (slow because of the xlsx reads, fast afterwards):

```bash
python -m swatad.convert      # writes data/processed/{swat,wadi}_{train,test}.parquet
```

### 3. Run an experiment

One run is one (dataset, model, seed):

```bash
python -m swatad.run --dataset swat --model gdn --seed 0
```

| Flag | Meaning |
|---|---|
| `--dataset {swat,wadi}` | which dataset |
| `--model {pca,iforest,usad,gdn}` | which detector (all four are interchangeable) |
| `--seed N` | RNG seed (default 0; the report uses 0, 1, 2) |
| `--epochs N` | override USAD/GDN epochs |
| `--quick` | 5% of train, 2 epochs. Smoke test only; metrics are meaningless and the model is not saved |
| `--reuse` | load the fitted model from `models/` and skip training |
| `--tag _x` | suffix on output file names (keeps variants apart) |
| `--config-from {swat,wadi}` | use the other dataset's hyperparameters (transfer experiment) |
| `--norm-stats {val,test}` | GDN error normalisation statistics (see Design notes) |
| `--drift-tol 1.5` | drop sensors that drift out of the train range on validation data |

Rough cost on CPU: PCA and iForest take seconds to minutes. USAD and GDN take minutes to tens of minutes per run (GDN on SWaT was about 5 min per run here).

Run the whole grid (3 seeds, all models, both datasets, plus the variants). It is resumable and skips runs whose `results/<name>.json` exists:

```bash
bash scripts/run_all.sh
```

Re-score without retraining. Each full (non-`--quick`) run pickles its fitted detector to `models/<name>.pkl`. Re-run the same command with `--reuse` to load it and redo scoring, thresholds and metrics:

```bash
python -m swatad.run --dataset swat --model gdn --seed 0 --reuse
```

Use identical dataset, model, seed and tag. `--epochs` and other model flags are ignored when reusing. Models trained before this feature existed have no pickle.

### 4. Run the tests

```bash
python -m pytest -q
```

## How to see results

```bash
python scripts/report.py     # results/*.json -> results/summary.md
python scripts/figures.py    # results/*_scores.npz -> results/fig_*.png
```

- **Console:** each run prints one line per threshold rule (point-wise F1, point-adjusted F1, composite F1, events detected).
- **`results/<dataset>_<model><tag>_s<seed>.json`:** all metrics for one run, plus config, training time and loss history.
- **`results/<dataset>_<model><tag>_s<seed>_scores.npz`:** raw anomaly scores, labels and validation scores for plotting or custom analysis. GDN also stores per-sensor scores.
- **`results/summary.md`:** mean ± std over seeds for every model × threshold rule, one table per dataset.
- **`results/fig_*.png`:** score traces with attacks shaded (`fig_trace_*`), point-wise vs point-adjusted bars (`fig_protocols_*`) and per-stage alarm heatmaps (`fig_stages_*`).
- **`results/published.json`:** the published numbers to compare against.

Only the figures, `summary.md` and `published.json` are tracked in git. The per-run JSON, `.npz` and logs are regenerated by running the grid, so they are git-ignored. `data/` and `models/` are also ignored.

## Execution flow

`python -m swatad.run` (`src/swatad/run.py:main`):

1. **Parse arguments** and build the output name `<dataset>_<model><tag>_s<seed>`.
2. **Load data** with `data.load_split`: median-downsample, drop the start-up transient, split off validation, min-max scale, and optionally drop drifting sensors.
3. **Build the detector** from `MODEL_DEFAULTS[(dataset, model)]` (paper hyperparameters), or from the other dataset with `--config-from`.
4. **Fit** on the train set, using validation data for early stopping and statistics (`det.fit(train, val)`). The fitted detector is pickled to `models/`. With `--reuse` it is loaded instead.
5. **Score** the test and validation sets (`det.score(x)`). It returns one anomaly score per time step.
6. **Choose thresholds:**
   - `best_f1`: oracle, picked with test labels. This is what most papers report.
   - `val_max`: the highest validation score (GDN's rule).
   - `val_q999`: the 99.9th percentile of validation scores.
7. **Evaluate** each threshold with `metrics.evaluate`: point-wise, point-adjusted, event-level and composite metrics, time to detect, ROC-AUC and PR-AUC.
8. **Plant-aware alarms** (`alarms.py`):
   - `val_q999_persist` applies a k-of-n persistence rule to the `val_q999` alarms (alarm if at least 3 of the last 5 steps exceed the threshold).
   - Models that expose per-sensor scores (GDN) also get `stage_q999` and `stage_q999_persist`. These use a separate threshold per process stage (the digit in the tag name, so `LIT301` is stage 3). An alarm names the stage that fired.
9. **Write outputs:** the JSON, the scores `.npz` and a printed summary line.

`scripts/run_all.sh` loops this over seeds and variants. `report.py` and `figures.py` aggregate the outputs.

## Architecture

```
data/raw  --convert-->  data/processed (Parquet)
                              |  data.load_split
                              v
                    Split(train, val, test, test_labels, columns)
                              |
        +---------+-----------+-----------+---------+
        |   pca   |  iforest  |   usad    |   gdn   |   <- same Detector interface
        +---------+-----------+-----------+---------+
                              |  score(x) -> (T,)   (+ sensor_scores for GDN)
                              v
              thresholds  ->  metrics.evaluate  ->  alarms (stage-wise, k-of-n)
                              |
                              v
               results/*.json + *_scores.npz  ->  report.py / figures.py
```

```
src/swatad/
  convert.py        raw xlsx/csv -> Parquet (one-off)
  data.py           load, downsample, scale, split, sliding windows, drift guard
  metrics.py        thresholds and all metrics
  alarms.py         stage_of, stage thresholds/alarms, k_of_n
  run.py            CLI: one (dataset, model, seed) run
  models/
    base.py         Detector protocol, pad_scores, seeding
    baselines.py    PCADetector, IForestDetector
    usad.py         USADDetector
    gdn.py          GDNDetector (dense graph attention, no torch_geometric)
scripts/            run_all.sh, report.py, figures.py
tests/              test_data, test_metrics, test_models, test_alarms, test_run
presentation/       interim slide decks
```

**The four models are interchangeable.** Each implements the same `Detector` protocol (`models/base.py`):

```python
det.fit(train: np.ndarray, val: np.ndarray)   # (T, N) scaled arrays
det.score(x: np.ndarray) -> np.ndarray        # shape (T,), higher = more anomalous
```

The runner, metrics, thresholds and report code only see that interface, so switching `--model` is the only change needed to compare detectors. Windowed models (USAD, GDN) front-pad their scores with the first valid score so that every score aligns with its time step and its label. A model that also offers `sensor_scores(x) -> (T, N)` (GDN) automatically gets the per-stage alarms.

| Model | Source | Score | Main settings |
|---|---|---|---|
| `pca` | Shyu et al. 2003 | squared reconstruction error | keep 95% of variance |
| `iforest` | Liu et al. 2008 | negative isolation score | 200 trees |
| `usad` | Audibert et al., KDD 2020 | `α‖W−AE1(W)‖² + β‖W−AE2(AE1(W))‖²` | window 12 (SWaT) / 10 (WADI), latent 40, α=β=0.5, 70 epochs |
| `gdn` | Deng & Hooi, AAAI 2021 | max over sensors of robust-normalised forecast error, 3-step average | window 5, embed 64/128, top-k 15/30 (SWaT/WADI), 50 epochs, patience 10 |

## Design notes and justification

**Preprocessing** (follows GDN so published numbers are comparable; see `data.py`):

1. **Strip column names, drop timestamps.** Raw SWaT headers contain stray spaces.
2. **Label cleaning.** Any SWaT label other than `Normal` counts as an attack (the files contain typos such as `A ttack`). WADI labels map `-1` to attack and `1` to normal.
3. **WADI column cleaning.** Drop columns that are all-NaN or constant in train (they would divide by zero when scaled), then forward-fill and fill any remaining NaN with 0.
4. **Median downsample by 10.** It cuts compute 10× and suppresses sensor noise. A block is labelled attack if at least 50% of its rows are.
5. **Drop the first 2,160 downsampled train rows** (6 h), because tanks are still filling and pumps are switching on.
6. **Min–max scale with train min/max, no clipping.** Out-of-range test values carry attack signal.
7. **Validation split.** The last 10% of train, in time order, is held out. Thresholds and score-normalisation statistics come from it, with no labels or test data.

**Evaluation beyond the papers:**
- Point-adjust (a whole attack counts as detected if any point is) inflates F1, so each run reports both point-wise and point-adjusted numbers.
- Event-level recall and precision, composite F1 (Garg et al. 2021) and time to detect show how many attacks are caught and how fast.
- The `best_f1` threshold needs test labels and is not deployable. `val_max` and `val_q999` use only normal data and show realistic performance. They are much lower than `best_f1` for every model.

**GDN normalisation.** The official GDN code normalises errors with test-set statistics. This repo defaults to validation statistics (stricter and deployable). `--norm-stats test --tag _teststats` reproduces the official behaviour.

**Drift guard** (`--drift-tol`, original modification). WADI sensor `2B_AIT_002_PV` is already about 4× outside its training range on normal validation data, so it flags most of the test set for reasons unrelated to attacks. The guard drops columns whose validation values exceed the train range by more than the tolerance. It uses normal data only, drops exactly this sensor on WADI, and drops nothing on SWaT. Its results use the `_drift` tag.

**Transfer.** `--config-from swat` runs WADI with SWaT's hyperparameters, without re-tuning (`_transfer` tag).

**Reproducibility.** Seeds are fixed everywhere (`torch.manual_seed`, `np.random.seed`, sklearn `random_state`). Reported numbers are mean ± std over seeds 0, 1, 2. Windows are strided views, not copies, to keep WADI within memory.
